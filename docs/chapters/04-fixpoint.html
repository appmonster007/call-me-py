Ask again until nothing changes

When the module reaches pick(True)(3) on line 15, nobody has analysed pick yet. Its return value is unknown. The fix is simple: keep re-analysing everything until a whole round learns nothing new.

This is the real trace of solve() on chapter 1's program, round by round.

Inside a single node there is a smaller version of the same loop: analyze runs the body again until the node's own environment stops changing. That handles loops, where a later line feeds an earlier one.

Why does pick(True) reach double too?

The analysis tracks tokens only. True carries none, so both outcomes of pick share one context, and square if flag else double is the union of both branches. Ignoring plain values is a deliberate trade: much cheaper, still sound, sometimes imprecise.

Why is the loop guaranteed to stop?

Everything the solver stores only grows: sets are unioned, never shrunk. And there are finitely many tokens and nodes, because the analysis widens whatever could grow forever: contexts past max_contexts, closures nested deeper than MAX_DEPTH, partials beyond MAX_PARTIAL_ARGS. A quantity that only grows and has a ceiling must stop growing.
