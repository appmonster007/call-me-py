Values that wait

Line 9 puts f into the list through b. Line 10 calls an element of a. Same list, two names: the analysis has to know they are one object.

Two simplifications keep this cheap. Indices are ignored: a[0] may be any element. And the heap only grows (weak updates): nothing stored is ever removed, because the analysis can't be sure a removal really happened.

Why not just add f to the value of b on line 9?

Because values are copied on assignment: changing b's value would not change a's. The Box is the one thing every alias shares, so storing into it is what lets a write reach every name, including lists passed into other functions, like register(handlers, f) filling the caller's list.

In the code

a mutable container token, one per allocation site
an allocation site: function, line, column
a list / set / dict literal or comprehension gets its Box
append, extend, insert, update, … become stores
weak update: heap[box] ∪= vals
a value plus everything stored in its boxes, transitively
a[0]: __getitem__ on objects, deref on containers
