Objects and hidden calls

Puppy().speak() runs a method defined two classes up, which calls self.sound(), defined one class up. With objects, every attribute raises one more question: where is it found?

Calls you never wrote

Python calls special methods behind a lot of syntax. Each is a call site the analyzer must see; otherwise the graph silently loses edges. The analyzer gives each of them a site kind (op, iter, with, attr) next to ordinary calls.

Why is the receiver of __iter__ Vec()@6:15, not one of the objects made on line 21?

v holds the result of +, and __add__ creates that object on line 6, column 15. Instances are named by where they are allocated, so the analysis keeps it apart from the two Vecs of line 21, each with its own fields.

In the code

runs a class body into its attribute table; records bases, metaclass, decorators
C3 linearisation over the user classes
calling a class: __new__, then __init__ on the new Instance
an attribute read: instance fields, MRO lookup, descriptors, properties, __getattr__
descriptor binding: function → bound method; classmethod; staticmethod
calls a special method on every Instance whose class defines it
operator → __op__, __rop__, __iop__
with: __enter__ in, __exit__ out
for and comprehensions: __iter__, then __next__
