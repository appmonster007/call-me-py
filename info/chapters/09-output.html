From state to graph

The solver's result is a graph of nodes, each a function in a context. People want a graph of functions. And we want evidence that it is right.

How do we know it's right?

Each case in examples/cases/ lists, in its docstring, the EXPECTED edges seen in a traced run of the program: the ground truth. It may also list edges a static analysis is allowed to add: STATIC_ONLY (dead code) and SPAWN (threads, tasks). Two tests per case:

  • test_sound: every expected edge is found. Missing edges are the serious failure.
  • test_precise: nothing is found outside expected ∪ allowed.

Pick a case. These are the results at the last info/build.py run.

To add a case, drop a file into examples/cases/<family>/ with a docstring in the case format. A new family is just a new folder; pytest.ini chooses which families run.

In the code

solver state → CallGraph: nodes, sorted edges, a unique label per node
the context-insensitive view: (caller, callee) function pairs
JSON: functions, call sites with targets, edges, contexts, context edges
Graphviz DOT; --contexts draws one box per node
expected ⊆ found
found ⊆ expected ∪ STATIC_ONLY ∪ SPAWN
feature families: which folders of cases run (--families, pytest.ini)
