Who does f() call?

Here is a whole program. Before reading on, guess: which functions can line 8 call?

Follow the values

The analyzer runs the program, but not on real values. Every expression evaluates to the set of functions it might be. Step through it with ▶ or the arrow keys.

Why a set, and not just one function?

One expression can hold different functions on different paths. Line 11, square if flag else double, evaluates to {square, double}: one of these, and we can't tell which. Calling every token in the set can only add edges, never miss one. That makes the analysis sound, at the price of some precision.

In the code

the token for a user function: which function, created while which node was running
an abstract value: a frozenset of tokens
evaluates an expression by dispatching on its AST type: e_Name, e_Call, …
a name's value: the local env, then enclosing functions, then builtins
evaluates the callee and the arguments, then applies
for each token in the callee's set: bind the arguments, record the edge, use its return value
