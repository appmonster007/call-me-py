call-me-py, explained

Who calls whom, when functions are values?

call-me-py reads a Python program without running it and draws its call graph, including calls through variables, parameters, return values, containers, objects and builtins. These pages explain how it works, one idea at a time, and point to the code that does it.

The pipeline

Five parts do the work. solver and interp form a loop: the solver keeps asking interp to re-analyse functions until nothing changes.

frontend

finds every function, its scope and its call sites

→
solver

re-analyses every (function, context) node until a round changes nothing

⇄
interp

evaluates one function body on abstract values; stubs/ covers the builtins

→
callgraph

collapses the solver state into a call graph

→
export

writes JSON or Graphviz DOT
